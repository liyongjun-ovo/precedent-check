# 前车之鉴 · precedent-check

动手前的经验输入检查 Skill：**反虚假优先 · 检索双源 · 发散 ≤5 → 收敛 ≤3 → 选定流程**。

在写代码、改文件、做方案之前，先检索业界通行方法与 GitHub 现成实现，列出前车之鉴、收敛到 3 条以内、选定一条流程，再开始做。

## IRON LAW

1. **没有来源标签，不许进结论。** 每条信息必须能追到本次会话的真实检索，或显式标 `[先验]`。
2. **前车之鉴没收敛到 ≤3 条、没写清保留与淘汰理由，不许进入执行。**

防的失败模式只有一个：**过早收敛**——第一个跑得通的方案就开工。

## 目录结构

```
precedent-check/
├── SKILL.md                                ← 入口：触发条件、反虚假、预算、模板
├── references/
│   ├── search-templates.md                 ← 检索模板与命中判定
│   ├── failure-patterns.md                 ← [先验] 失败模式自查清单
│   └── flow-design.md                      ← 收敛与候选流程检查
└── examples/
    └── example-run.md                      ← standard 档完整示例
```

入口是 `SKILL.md`；`references/` 与 `examples/` 是按其指示按需加载的支撑文件。

## 核心流程

1. 判档（fast / standard / deep / 跳过）
2. 写三行：问题 · 成功标准 · 不做
3. 双源检索：业界方法（web 三段式）+ GitHub 现成实现（主检索地），按预算硬停
4. 发散前车之鉴（≤5 条，每条带来源标签）
5. 收敛到 ≤3 条 + 保留/淘汰理由
6. 候选流程 A/B + 选定
7. 按固定模板成文，交付前跑反虚假自查

## 使用

适用于：多步骤实现、跨文件改动、方案选型、架构设计、引入新依赖，或用户说"认真设计""先规划""别急着写""先看看别人怎么做""有没有现成轮子"。

不适用于：问答、查询、格式转换、单行修改、有明确先例的常规任务，或用户说"直接做"。
