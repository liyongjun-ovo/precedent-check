# 通用工程失败模式自查清单 `[先验]`

**【[先验] 通用工程经验，非本次检索结果，不得作为检索证据引用】** 本文件整体来源为 `[先验]`，不含任何仓库名、链接、版本号、采用度数字、日期——它只提供「问题」，不提供「答案」，更不提供证据。

用法：检索前拿它选检索方向；收敛时拿它检查理由是否具体；交付前逐条勾选。凡由本清单得出的判断，来源标签一律写 `[先验]`；要证据就另行检索。

## 0. 三种用法

| 时机 | 用它做什么 | 产出 |
|------|-----------|------|
| 检索前 | 挑最可能命中的两三条，转成检索关键词 | 检索方向 |
| 收敛时 | 检查候选与淘汰理由是否具体 | 更硬的淘汰理由 |
| 交付前 | 逐条自查，勾不上的写 open questions | 自查记录 |

## 1. 核心失败模式：过早收敛（第一个可行方案就开工）

**症状**：脑子里出现第一个能跑通的方案，立刻动手；检索、比较、验证全部省略。

任一条答「是」即触发：

- [ ] 我只评估了一个候选就准备动手？
- [ ] 我选它是因为「我最熟」，而不是「最对齐成功标准」？
- [ ] 候选流程 A / B 其实是同一路线的两种措辞（伪对比）？
- [ ] 我没有主动为当前方案找过反例？
- [ ] 我停检索的真实原因是「再查下去麻烦」，而不是「已经够用」？

### 1.1 变体清单

| 变体 | 自查问题 |
|------|---------|
| 单候选开工 | 两个候选是否来自真正不同的路线？ |
| 把熟悉当最优 | 判定理由是「我会用」还是「对齐成功标准」？ |
| 规模错配地引入重依赖 | 引入的框架是否远大于任务本身？ |
| 忽略迁移与回滚成本 | 选错了能否退回？回退动作与代价写了吗？ |
| 忽略许可与维护状态 | 许可证兼容吗？最后维护时间看过吗？ |
| 把性能假设当事实 | 有没有把「应该更快」写进结论？ |
| 只查「怎么做」不查「哪里会翻车」 | 三段式检索的 pitfalls 段跑了吗？ |
| 检索当装饰 | 检索结果改变了哪一个决策？一个都没有？ |
| 凑数式发散 | 列条目是为了「看起来查过」吗？ |
| 收敛理由空话 | 淘汰理由能否落到「不适用 / 证据弱 / 规模不匹配」之一？ |

## 2. 问题定义阶段

- [ ] 一句话问题里，成功标准是可验证的判据，还是形容词？
- [ ] 「不做」边界写了吗？没写边界，范围一定会在执行中膨胀。
- [ ] 区分了「用户字面要求」与「用户真实目标」吗？两者冲突时先问了吗？
- [ ] 我是不是在解决一个自己重新定义过的问题？
- [ ] 问题里的隐含前提（例如「必须重写」「必须用某技术」）被验证过吗？

## 3. 证据与来源阶段

- [ ] 每条结论都有来源标签？
- [ ] 有没有把先验写成检索结果？
- [ ] 有没有「看起来合理但没见过」的名字、链接、数字混在结论里？
- [ ] 检索到的信息是否超出「能改变决策」的必要范围？
- [ ] 无果的方向，写的是「本次未检索到」而不是「不存在」？
- [ ] 来源标签与内容是否匹配（`[GH:...]` 只用于真实仓库，`[web:...]` 只用于真实页面）？

## 4. 方案与规模阶段

- [ ] 方案复杂度与任务规模同量级吗？
- [ ] 试过「不引入任何新依赖」的最简方案吗？
- [ ] 把可逆的小决定当成了不可逆的大决定（或反过来）吗？
- [ ] 方案依赖的隐含能力（运行环境、权限、预算）是否具备？
- [ ] 有没有为了「技术更先进」而牺牲可维护性？
- [ ] 失败时存在降级路径吗？还是只有全成或全败？

## 5. 迁移、回滚与成本

- [ ] 改动会不会产生需要长期维护的兼容层？
- [ ] 回滚需要重做哪些部分？成本量级是多少？
- [ ] 数据 / 状态迁移是否可逆？不可逆的部分单独标出了吗？
- [ ] 是否把迁移成本留给「以后」而没有写下来？
- [ ] 选错的代价是否已和「少查一轮」的收益做过对比？

## 6. 安全与合规阶段

- [ ] 新依赖的许可证与本项目兼容吗？
- [ ] 是否引入了不必要的网络访问、执行权限或外部服务？
- [ ] 涉及敏感数据的路径，是否明确了不外发、不落盘？
- [ ] 有没有把「没人反对」当成「没有风险」？

## 7. 本 skill 边界自查

- [ ] 我是否已经开始拆执行步骤、列文件清单、估工时？（是 → 越界，退回）
- [ ] 我是否把候选流程写成了执行计划？
- [ ] 我是否为了让文档「更完整」而保留了不改变决策的条目？

## 8. 勾选结果怎么处理

| 情况 | 处理 |
|------|------|
| 勾不上（回答不了） | 写进 open questions，标 [未验证] |
| 勾上了（存在该风险） | 它是检索方向，不是结论 |
| 已确认有风险 | 写进候选流程的「风险」列，并配对策 |

## 9. 禁止用法

- 不得把本文件当检索结果引用，不得写「根据工程经验检索发现」
- 不得从本文件推出具体仓库、链接、版本、数字、日期
- 不得用本清单替代检索：它只告诉你该查什么，不告诉你查到了什么
