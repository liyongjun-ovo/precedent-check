# 候选流程设计检查清单

本文件只管「选哪条路线、为什么选它」，不管执行拆解：拆步骤、列文件、估工时都是 planning 的事，写到这里即视为越界。

**来源规则**：候选流程可以来自本次检索（带 `[GH:...]` / `[web:...]`），也可以来自先验（标 `[先验]`）；两类不得混写成一种。

## 1. 候选准入条件

一条路线要能进候选，先过五道门（任一项不过就不算候选）：

- [ ] 能写出主干：三到五个阶段级动作，不含执行细节
- [ ] 能对齐成功标准：逐条说明覆盖哪一条
- [ ] 在「不做」边界内
- [ ] 有来源：本次检索命中，或明确标 `[先验]`
- [ ] 与另一候选是不同路线，不是同一路线的措辞变体

## 2. 至少两个候选（A / B）

每个候选一行，三样缺一不可（与 SKILL.md 的产出物模板一致）：

```
• A：主干（只到路线）｜优点：对齐成功标准第几条｜风险：触发条件 → 后果 → 对策
• B：同上三格，写出与 A 不同的路线
```

**主干写到哪一层**：

- 只到「方案路线」：用什么机制、复用哪个现成实现、走什么架构
- 不写：文件清单、函数名、步骤编号、命令、工期
- 判据：主干两行内说得清；超过两行，说明已经滑进 planning
- 主干里的每个构件，都要能回答「为什么是它，不是另一个」

**优点 / 风险怎么写**：

- 优点必须落到成功标准的一条上，不写「更优雅」「更先进」这类评价词
- 风险写「触发条件 + 后果 + 对策」，不写「可能有一些问题」
- 每个风险配一句对策：规避 / 监控 / 明确接受；无对策的风险不得留在选定流程里
- 风险按「会不会让方案失败」排序，不按「容不容易解决」排序

### 2.1 常见无效候选

| 无效候选 | 为什么无效 | 处理 |
|---------|-----------|------|
| A 与 B 只差命名或实现细节 | 伪对比，等价于单候选开工 | 重写 B；或承认只有单候选，并说明为何可接受 |
| B 是「什么都不做」 | 降级也是方案，但要写代价 | 补上「不做的代价」再比较 |
| B 的主干写不出来 | 说明还没想清，不是候选 | 降为 open question |
| B 只覆盖边角需求 | 不构成路线对比 | 剔除 |

## 3. 选定检查（逐条过）

- [ ] 对齐成功标准：A 覆盖哪几条？没覆盖的缺口怎么补？
- [ ] 不越边界：A 是否把「不做」范围内的事顺手做了？
- [ ] 风险有对策：A 的每个风险都有规避 / 监控 / 接受？
- [ ] 可逆性：选错了多久能退回？回退动作是什么？
- [ ] 规模匹配：方案复杂度与任务规模是否同量级？
- [ ] 依赖代价：新增依赖、学习成本、维护成本是否已计入？
- [ ] 放弃理由具体：B 被淘汰，是因为不适用 / 证据弱 / 规模不匹配 / 风险无对策中的哪一条？
- [ ] 可复核：理由能否被第三人按文档复现，而不是一句「综合考虑」？
- [ ] 理由有检索支撑：选定理由是否只靠 `[先验]`？只靠 `[先验]` 时，必须在 open questions 写明缺少检索支撑

### 3.1 放弃理由合格 / 不合格对照

| 不合格 | 合格 |
|--------|------|
| B 不太合适 | B 需要引入整套框架，而本任务只改一处逻辑，规模不匹配 |
| B 太复杂 | B 的主干含三处跨边界改动，越出「不做」范围 |
| 综合考虑选 A | A 覆盖成功标准前两条且回滚只需撤销一处改动；B 缺第一条且主要风险无对策 |

## 4. 收敛检查（前车之鉴 ≤ 3 条）

- [ ] 保留的每条是否真的改变了一个决策？没改变 → 删
- [ ] 保留条目是否分别对应 A / B 判断中的某个具体点？
- [ ] 保留条目之间是否信息重叠？重叠时只留决策增量最大的那条，其余归入「不适用」淘汰
- [ ] 淘汰理由是否落在：不适用（含前提不同、与成功标准无关、与已列条目信息重叠无增量）/ 证据弱 / 规模不匹配
- [ ] 收敛理由是否只引用已列出的条目，没有引入未列出的信息
- [ ] 是否存在凑数保留（为了「有 3 条」而留）？
- [ ] ≤ 3 条硬上限是否遵守？

### 4.1 淘汰理由类型

| 类型（对外只呈现三类） | 判据 | 写法示例 |
|----------------------|------|---------|
| 不适用 | 前提假设与本任务不同；与成功标准无关；与已列条目信息重叠、删掉它收敛结论不变 | 该做法假设存在某前置条件，本任务没有；属性能优化，成功标准不含性能；与保留的第 1 条重复，删去后选定结论不变 |
| 证据弱 | 只有单一来源或未经验证 | 仅一条来源且无实现佐证，降为 open question |
| 规模不匹配 | 依赖 / 改动量级远超任务 | 为改一处引入整套框架，代价高于收益 |

## 5. 选定之后交出去什么

本 skill 的输出止于「选定」，交付四样东西（给 planning 或人工执行方）：

1. 选定流程 A 的主干
2. 理由：对齐哪条成功标准、为何优于 B
3. 放弃 B 的具体原因
4. 已知风险与对策，以及 open questions / 未检索到

### 5.1 交接边界

- 交出的是「路线」，不是「步骤」
- 若对方要求拆步骤：说明那属于 planning，不在本 skill 范围
- 若选定后才发现边界外需求：回到第 1 节重判，不要在执行中偷偷扩范围

## 6. 越界自检（交付前最后一遍）

- [ ] 候选流程里是否出现步骤编号、文件清单、命令、工期
- [ ] 「选定」之后是否继续写了执行计划
- [ ] 是否把 planning 的产物塞进了候选流程
- [ ] 风险列是否只是形容词，没有触发条件与后果
- [ ] 放弃理由是否可以被独立复核
